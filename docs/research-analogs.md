# VKDW и аналоги на GitHub: исследование и выводы

Дата: 2026-10-12. Код при исследовании не менялся.

План изменений, который вытекает из этого исследования, лежит в [plan-improvements.md](plan-improvements.md).

## Как искали

- Поиск по GitHub API: `vk video downloader`, `vkvideo downloader`, `vk playlist downloader`, `vkontakte video downloader`, `vkvideo` и `vk video playlist` с фильтром по языку (Python, Go, C#).
- Прочитаны README двадцати проектов, похожих на VKDW, и исходник VK-экстрактора yt-dlp (`yt_dlp/extractor/vk.py`).
- Музыкальные загрузчики VK (их много) отброшены: они про аудио, не про видео.

## Главный вывод

**Прямого аналога у VKDW нет.** Найденные проекты делятся на три группы:

1. **Расширения и юзерскрипты** скачивают одно видео со страницы, на которой вы стоите.
2. **Универсальные программы на yt-dlp** (napotom, Magerko, elengrab, NewYoutubeDownloader) умеют очередь и параллельные загрузки, но про VK знают ровно то, что знает yt-dlp.
3. **Консольные утилиты и боты** решают одну узкую задачу.

Нативного Windows-приложения, которое работает с плейлистами и целыми сообществами VK, выбирает ролики галочками и помнит, что уже скачано, не нашлось. Ближе всего по идее vkvideo-sync (подписка на плейлисты), но это консольная утилита без Windows.

## Что в VKDW уже есть и сделано хорошо

- **Свой клиент VK API с анонимным токеном** (`vkdw/vk_client.py`) вместо yt-dlp и разбора HTML. Вёрстка сайта на работу не влияет. Сообщества и страницы людей открываются. По README vkvideo-sync, у yt-dlp загрузка всех видео канала (`vk:uservideos`) сейчас падает с ошибкой «Unable to extract cursor data».
- **Много видов ссылок:** плейлисты (новые и старые `section=album_`), видео, клипы, `?z=video`, `@name`, `club` / `public` / `id`, короткие имена, несколько ссылок сразу.
- **Точный выбор роликов:** галочки, Shift-диапазон, поиск по названию и автору, «Все». В GUI на yt-dlp такого обычно нет: там качают плейлист целиком или по номерам.
- **Очередь, которая переживает сбой:** `session.json` с запасным `session.bad.json`, пауза и продолжение, «Повторить неудачные», удаление в любом состоянии, вставка «следующим». Токен не сохраняется, а при продолжении его спрашивают снова.
- **«Уже есть» до скачивания** и **закладки как подписка** со счётчиком новых роликов.
- **Понятные ошибки:** деление на input / access / network, подсказка про VPN, F5 перечитывает доступность роликов до скачивания.
- **Аккуратные файлы:** запись в `.part` и переименование в конце; ширина номера по длине плейлиста; имя по дате для сообществ и сборников, чтобы новые ролики не сдвигали номера.
- **Удобство:** русский и английский с переключением без перезапуска, темы, кеш обложек, уведомления в трее, Ctrl+V, перетаскивание, подсказка про ссылку в буфере обмена, горячие клавиши, журнал со счётчиком непрочитанных ошибок.
- **Тесты:** 7 файлов, включая тесты окна в режиме offscreen. У большинства аналогов тестов нет совсем.

## В чём VKDW лучше остальных

1. **Единственное найденное GUI-приложение именно для VK, которое работает с плейлистами и сообществами целиком:** «Загрузить ещё», меню «Плейлисты» сообщества.
2. **Сборник** из роликов из разных мест, который скачивается как один плейлист. Такого нет ни у кого.
3. **«Уже есть», закладки и счётчик новых роликов** вместе закрывают сценарий «досмотреть сериал» в GUI под Windows. Похожее есть только у vkvideo-sync, и то в консоли и без Windows.
4. **Нет зависимости от yt-dlp.** Аналоги ломаются, когда VK меняет сайт, поэтому им приходится всё время обновлять yt-dlp (у napotom и Magerko для этого встроено автообновление, а vk-scribe советует `uv add yt-dlp -U`). Обратная сторона: изменения API VK придётся чинить самим.
5. **Восстановление после сбоя и разбор ошибок по причинам** продуманнее, чем у всех найденных GUI.

## Чего не хватает (по сравнению с аналогами и по чтению кода)

### Найденные ошибки

- **Ролики только с HLS/DASH не скачиваются (проверено).** `_download_with_ffmpeg` пишет в файл `….mp4.part`. ffmpeg определяет формат по расширению, `.part` не узнаёт и падает с ошибкой «Error initializing the muxer … Invalid argument». Проверено на ffmpeg 8.0.1, который стоит на этой машине. Если указать `-f mp4`, файл записывается.
- **ffmpeg может зависнуть (вероятно, не проверено).** stderr передаётся в канал, но читается только после завершения процесса. ffmpeg постоянно пишет туда статистику. Когда буфер заполнится, ffmpeg встанет до 6-часового таймаута. Эта ошибка проявится, как только исправят первую.

### Загрузка

- У HLS нет прогресса (`on_progress(0, 0, 0)`), а выбранное качество для HLS не учитывается.
- Нет докачки: `.part` удаляется при остановке и при повторной попытке.
- MP4 качается в одно соединение. По данным vkvideo-sync, CDN VK ограничивает скорость одного соединения, а параллельные Range-запросы заметно ускоряют загрузку.
- Нет параллельных загрузок нескольких роликов (napotom, Magerko, elengrab, NewYoutubeDownloader).
- Одинаковые имена: два ролика с одним названием и датой в сообществе или сборнике дают одно имя файла, и второй молча пропускается как «уже есть».

### Учёт скачанного

- «Уже есть» работает только по имени файла. Если ролик переименовали в VK или вы сменили папку, он скачается снова. У vkvideo-sync и vk-scribe есть архив по id.
- Закладки проверяются только при открытии. Нет кнопки «проверить все и поставить новое в очередь».

### Содержимое

- Нет метаданных в файле (название, дата, автор, описание), субтитров, глав. yt-dlp всё это достаёт.
- Нет режима «только звук» (napotom, Magerko, NewYoutubeDownloader).
- Нет файла `.m3u` для плейлиста (NewYoutubeDownloader).

### Ссылки и вход

- Не поддерживаются `video_ext.php?oid=…&id=…`, `vk.cc` / `vk.link` и посты на стене. Для прямых эфиров нет отдельного сообщения.
- Нельзя загрузить `.txt` со списком ссылок.
- Для закрытых плейлистов нужен access token, который пользователь сам должен где-то взять. У аналогов вход через cookies или браузер.

### Мелочи

- ffmpeg ищется только в PATH. Аналоги кладут его рядом с программой или предлагают установить.
- Нет действия после очереди (выключить компьютер), ограничения скорости, проверки свободного места.

## Что брать не стоит

- **Переход на yt-dlp.** Потеряем страницы сообществ, которые у него сейчас сломаны, и независимость от его обновлений.
- **Сборка в frozen exe.** Правило VPN, которое даёт VK российский IP, привязано к имени процесса `python.exe`.
- **Медиатека с плеером** (elengrab). Это другой продукт.
- **Обход ограничений через WARP и цепочки прокси** (бот). Это противоречит позиции из README: «Программа не обходит ограничения VK».
