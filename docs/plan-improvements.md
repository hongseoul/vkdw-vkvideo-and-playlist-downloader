## Этап 1. Исправить HLS (срочно, небольшая правка)

### Шаг 1. ffmpeg не может записать `.mp4.part` — ошибка проверена

**Что не так.** `_download_with_ffmpeg` (`vkdw/downloader.py:155`) передаёт ffmpeg выходной файл `….mp4.part`. ffmpeg выбирает формат по расширению и падает: «Error initializing the muxer for test.mp4.part: Invalid argument». Проверено на ffmpeg 8.0.1. Значит, любой ролик без прямого MP4 сейчас уходит в ошибку.

**Что сделать.** Добавить `-f mp4` перед именем выходного файла.

**Тест.** Собирать команду в отдельной функции (например, `ffmpeg_command(url, dest)`) и проверять в `tests/test_core.py`, что в ней есть `-f mp4`. Можно добавить тест, который пропускается без ffmpeg: прогнать `ffmpeg -f lavfi -i testsrc=duration=1` в `.mp4.part` во временной папке.

### Шаг 2. ffmpeg может зависнуть из-за непрочитанного stderr

**Что не так.** `stderr=subprocess.PIPE` читается только после выхода процесса (`downloader.py:172-189`). ffmpeg постоянно пишет туда статистику, буфер канала заполняется, и ffmpeg останавливается до 6-часового таймаута.

**Что сделать.**
- Запускать ffmpeg с `-nostats -loglevel error`, чтобы в stderr шли только ошибки.
- Читать stderr в отдельном потоке (daemon) в ограниченный буфер, например `collections.deque(maxlen=50)`. Последнюю строку брать оттуда, как сейчас.
- Прогресс получать через `-progress pipe:1` (см. шаг 3), stdout тоже читать в потоке.

**Тест.** Подложить фейковый «ffmpeg» — скрипт на Python, который пишет в stderr больше 1 МБ и выходит с 0. Через `shutil.which` или параметр функции он подставляется вместо ffmpeg. Загрузка должна закончиться, а не повиснуть.

### Шаг 3. Прогресс и качество для HLS

**Что не так.** Вызывается `on_progress(0, 0, 0)`, поэтому внизу окна нет процентов. `max_height` для HLS не учитывается: ffmpeg сам берёт лучший поток.

**Что сделать.**
- **Прогресс.** `-progress pipe:1` выдаёт строки `out_time_us=…` и `total_size=…`. Проценты считать по `item.duration` (это поле уже есть у `VideoItem`). Передавать `on_progress(done_us, total_us, bytes_per_sec)`, но окно ждёт байты, поэтому проще вызывать `on_progress(total_size, оценка_размера, скорость)`, где оценка = `total_size / доля_времени`. Посмотреть, как окно показывает `("file", …)` события (`controller.py:615`, обработка в `ui/window.py`). Возможно, лучше добавить в событие отдельный признак «доля», а не изображать байты.
- **Качество.** Для `hls` скачать master-плейлист через `urllib` (с теми же заголовками), разобрать `#EXT-X-STREAM-INF: … RESOLUTION=WxH`, выбрать вариант по тем же правилам, что `choose_source` для MP4 (не выше `max_height`, иначе самый низкий), и отдать ffmpeg URL этого варианта. Если разобрать не получилось, отдать master как сейчас. Метку качества (`label`) возвращать `"720p"` и т. п. вместо `"HLS"`.
- Для `dash_sep` оставить как есть (ffmpeg сам берёт видео и звук).

**Тест.** Разбор master-плейлиста — чистая функция, её проверить на строке с 3–4 вариантами. Проверить выбор при `max_height=None`, 720 и 144.

## Этап 2. Докачка и одинаковые имена

### Шаг 4. Докачка MP4 вместо загрузки заново

**Что не так.** `.part` удаляется в начале каждой попытки и при остановке (`downloader.py:98-99`, `109-111`). Остановка или обрыв сети в середине часового ролика означают загрузку с нуля.

**Что сделать.**
- Для `mp4` не удалять `.part` при `Cancelled` и при сетевых ошибках.
- При старте, если `.part` есть и его размер больше 0, слать `Range: bytes=<size>-`.
  - Ответ `206` с `Content-Range: bytes N-…/TOTAL`: дописывать в конец (`open("ab")`), прогресс считать от `N` до `TOTAL`.
  - Ответ `200`: сервер не поддерживает Range, перезаписать файл с нуля.
  - Ответ `416`: файл, вероятно, уже целиком; сравнить размер с `TOTAL` или начать заново.
- Ссылки VK подписаны и живут ограниченное время, поэтому URL каждый раз берётся заново через `client.video_files` (так и сейчас). Если у нового URL `TOTAL` не совпадает с размером, под который качали, начать заново. Записывать ожидаемый размер рядом, например в `….part.size`, или полагаться на `Content-Range`.
- Для HLS `.part` по-прежнему удалять: ffmpeg не умеет докачивать.
- В README (раздел «Если программа закрылась») заменить «недокачанный ролик скачается заново» на описание докачки.

**Тест.** Локальный HTTP-сервер в тесте (`http.server` в потоке), который поддерживает Range. Сценарии: обрыв на середине и продолжение, файл в итоге совпадает по байтам; сервер без Range — файл перекачан целиком.

### Шаг 5. Одинаковые имена файлов

**Что не так.** `output_path` (`downloader.py:64`) строит имя по названию (и дате или номеру). В сообществе или сборнике два ролика с одним названием за один день дают одно имя. В одном списке второй молча считается «уже есть» (`is_saved`). Для `number` совпадений нет, потому что номер уникален.

**Что сделать.** Сделать правило детерминированным, чтобы `saved_ids` (`controller.py:74`) и загрузка всегда получали одно и то же имя:
- Новая функция, например `output_names(items, naming, width) -> dict[raw_id, Path]`. Она строит имена для всего списка сразу и тем роликам, у которых имя совпадает с чьим-то ещё, добавляет ` [owner_video]` перед `.mp4`.
- `_execute` (`controller.py:599`) и `saved_ids` берут имя оттуда, а не из `output_path` по одному ролику.
- Ограничение: у сообщества список читается порциями по 1000, и совпадение между порциями при первом открытии не будет видно. Это приемлемо; записать в комментарии.
- Уже скачанные раньше файлы без `[id]` при совпадении перестанут находиться как «уже есть». Решение: если файл с `[id]` не найден, проверять и старое имя без `[id]` для первого из одинаковых роликов.

**Тест.** Два `VideoItem` с одинаковым названием и датой → два разных пути; три ролика, где совпадают только два → суффикс только у них; `saved_ids` видит файл с суффиксом.

## Этап 3. Учёт скачанного и закладки

### Шаг 6. Архив скачанного по id

**Что не так.** «Уже есть» работает только по имени файла в текущей папке. Если ролик переименовали в VK или вы сменили папку, он скачается заново.

**Что сделать.**
- Новый модуль `vkdw/archive.py`: файл `%LOCALAPPDATA%\VKDW\archive.json` (путь как у `session_path()` в `vkdw/session.py:22`), запись через `write_atomic` из `vkdw/settings.py`. Содержимое: `{"owner_video": "полный путь к файлу"}`. Ключ — `_short_id` без access key (`controller.py:99`).
- Запись добавляется только после `partial.replace(dest)`, то есть когда файл действительно готов. Делать это в `_execute`, а не в `downloader.py`.
- Проверка «уже есть»: ролик считается скачанным, если файл найден по имени (как сейчас) **или** путь из архива существует и файл не пустой. Если файла по пути из архива уже нет, ролик качается снова, а запись не мешает.
- В окне различать «уже есть в этой папке» и «скачан раньше в другое место» (новая строка в `i18n/ru.py` и `i18n/en.py`). Для второго случая показывать путь в подсказке и давать «Показать в папке».
- Не делать из архива «запрет»: удалили файл — можно скачать снова. В этом отличие от vkvideo-sync, и это сознательно.

**Тест.** Файл записан → запись есть; файл удалён → ролик снова не скачан; переименованный в VK ролик (то же id, другое название) находится через архив.

### Шаг 7. «Проверить все закладки»

**Что не так.** Новые ролики видно только при открытии каждой закладки по очереди.

**Что сделать.**
- Кнопка в меню «Закладки»: «Проверить все». В фоне по очереди читать каждую закладку (`client.open_target(mark.target)`, для сообществ — первую порцию), считать новые ролики через `saved_ids` и архив и обновлять `count` через `bookmarks.refreshed`.
- В списке закладок показывать бейдж «+N новых».
- Действие «Скачать новое» по закладке и «Скачать новое во всех» собирает задания очереди через существующий `make_job` (`controller.py:282`) только из новых роликов, с папкой и качеством из текущих настроек.
- По желанию: флажок в ⚙ «Проверять закладки при запуске». Только проверка и бейджи, без автоматической загрузки.
- Читать VK с паузой между закладками (как `_call` делает повторы при ошибке 6), чтобы не упереться в ограничение частоты запросов.

**Тест.** Фейковый клиент, как в `OwnerPageTests` (`tests/test_core.py:142`): две закладки, у одной два новых ролика → бейдж 2, задание очереди из двух роликов.

## Этап 4. Скорость

### Шаг 8. MP4 в несколько соединений

**Что не так.** Один ролик качается одним соединением. По данным vkvideo-sync, CDN VK ограничивает скорость одного соединения.

**Что сделать.**
- Сначала замерить: скачать один и тот же большой ролик через VPN в 1 и в 4 соединения. Если выигрыша нет, шаг не делать.
- Если выигрыш есть: при `Accept-Ranges: bytes` и известном размере делить файл на 4–8 частей и качать их потоками `urllib` в один `.part` (`seek` + `write` по смещению, файл заранее нужного размера). Отмена — через тот же `cancel`. Прогресс — сумма частей.
- Докачку (шаг 4) делать по частям: хранить, сколько скачано в каждой части (например, в `….part.json`).
- Число соединений вынести в константу, в настройки — только если понадобится.

**Тест.** Тот же локальный сервер с Range, что в шаге 4: файл из 4 частей совпадает по байтам; отмена в середине оставляет корректную докачку.

## Этап 6. Ссылки, вход и мелочи

### Шаг 13. Новые виды ссылок (`vkdw/vk_client.py`, `parse_target`)

- `vk.com/video_ext.php?oid=-123&id=456&hash=…` → видео `(-123, 456)`, `hash` пока отбросить.
- `vk.cc/…` и `vk.link/…` → один HEAD/GET без следования редиректу, взять `Location` и разобрать его. Это сетевой запрос, поэтому делать его не в `parse_target`, а при открытии ссылки (в `controller.open_link`).
- `vk.com/wall-123_456` → `wall.getById`, собрать видео из вложений и открыть как сборник.
- Прямой эфир: если в ответе `video.get` есть признак эфира (`live`), показывать отдельную понятную ошибку.
- Тесты — в `ParseTests` (`tests/test_core.py:32`).

### Шаг 14. Список ссылок из `.txt`

- Перетаскивание `.txt` в окно: прочитать файл и отдать текст в существующий разбор нескольких ссылок (`parse_targets`), так же как вставку нескольких ссылок.
- В меню списка: «Скопировать ссылки отмеченных».

### Шаг 15. Вход для закрытых плейлистов

- В диалог токена добавить короткую инструкцию и кнопку, которая открывает в браузере страницу получения токена с правом `video`.
- Вход через cookies или встроенный браузер не делать: это QtWebEngine (+100 МБ) и хранение чужих сессий.

### Шаг 16. ffmpeg рядом с программой

- `_download_with_ffmpeg`: искать сначала `ffmpeg.exe` в корне проекта и в `%LOCALAPPDATA%\VKDW\`, потом `shutil.which`.
- Если ffmpeg нет и ролик требует его, писать в журнал подсказку `winget install ffmpeg` (новая строка в i18n).

### Шаг 17. Мелочи

- Действие после очереди в ⚙: «ничего» / «выключить компьютер» (`shutdown /s /t 60` с возможностью отмены).
- Перед началом задания проверять свободное место (`shutil.disk_usage`). Если меньше 1 ГБ, писать предупреждение в журнал; если `Content-Length` первого ролика больше свободного места — ставить очередь на паузу.
- Ограничение скорости — только если попросят.

## Этап 7. Релиз (exe)

Для разработки программа запускается через `python.exe` (см. память о VPN). Для релиза собирается отдельный exe. VPN-правило у каждого пользователя своё, поэтому его не привязываем к имени процесса.

### Шаг 18. Сборка exe

- PyInstaller, сначала папочная сборка (`--onedir`), затем при необходимости один файл.

- Подпись exe или инструкция на случай ложного срабатывания антивируса.
- Способ распространения обновлений.
